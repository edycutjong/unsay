This is the screen, not a picture of one. It holds an MCP session against the running server and repaints when notifications/resources/updated arrives. The status chip on the device says which path is carrying the change — a native subscription, or the whats_changed tool, which is the fallback for a host that cannot subscribe. Both are built, and this page exercises whichever one is actually available.

With no server answering, the chip reads SEED · NOT LIVE and the screen shows the committed record from src/seed.ts with its pinned clock. It never invents a correction: no strike-through and no amber dot can appear unless a real revision arrived.

Serve this page from the server’s own origin. The Unsay server sends no CORS headers and answers a preflight with 405, so a browser blocks these requests before they leave when the page is opened from file:// or a different port. Same origin, and everything above is live.

Press F for presentation mode — the page chrome disappears and the device fills the display, which is what the demo video films. Open the clinician screen in another window and publish a revision to watch this one retract.

Unsay relays what a clinician wrote. It does not generate clinical guidance and is not a medical device.
